✨ Annotation Tool — User Manual

🚀 Quick Start — The 3-Step Routine

Annotating a resume is a 3-step dance. Master these and you'll be flying through the queue!

  1. Pick your entity label from the palette on the right panel — click a coloured button (e.g. Person Name, Email Address) OR press its keyboard shortcut number. The active label will glow with a white border.
  2. Highlight the text in the resume on the left — click and drag across the words you want to label. Release the mouse and the annotation appears as a coloured highlight instantly.
  3. Save your work — press Ctrl S to save a draft anytime, or click ✅ Mark Complete when the resume is fully annotated and ready for export.

🖱️ Highlighting — Tips for Accurate Selection

💡 Always select an entity label first, THEN drag to highlight. Dragging without an active label does nothing — the text stays unselected.
⚠️ Avoid dragging into coloured label chips — the tiny floating tags above highlighted text (like "PERSON", "EMAIL"). If your selection clips one, a warning toast appears. Just try again, starting your drag slightly lower or to the side of the chip.
⚠️ Overlapping annotations on the same layer are not allowed. If you try to highlight text that's already labelled, you'll get a warning. Delete the existing annotation first, then re-label.
✅ The tool automatically trims leading and trailing whitespace from your selection — no need to be pixel-perfect at the word edges.
✅ Clicking any coloured highlight in the text panel will jump to that annotation in the Labels list tab on the right.

🗂️ Side Panel — What Each Section Does

  1. 🎨 Entity Palette (top, always visible) — Your label buttons, organised by category: Personal, Professional, Education, Skills. Buttons with a keyboard shortcut show the key hint on the right side of the button.
  2. 📋 Labels tab — Lists every annotation you've added. Each item shows the entity type, a preview of the labelled text, and a ✕ delete button. The badge on the tab shows the total count.
  3. 🏷️ BIO tab — Previews the BIO-encoded training format (B-ENTITY = beginning of entity, I-ENTITY = inside entity, O = outside / no label). Hit 🔄 Refresh after adding annotations. This is exactly what your NER model sees during training!
  4. 🧩 Edge tab — Scans the resume for tricky annotation patterns like date ranges containing "Present" or "Organisation, Location" combos that need splitting. Hit 🔍 Scan to run the check and see hints.
  5. 🧠 Classify tab — Shows automatically predicted Function and Industry based on the resume text. You can correct them using the dropdowns and save. These values will appear in the exported talent database profiles.

🔧 Toolbar Buttons Explained

  1. 🤖 Pre-Annotate — Runs the auto-labeller with a confidence threshold you choose (0.0–1.0, default 0.6). It adds suggested labels without overwriting your existing human annotations.
  2. 🧩 Edge Cases — Jumps to the Edge tab and scans the text for commonly mis-annotated patterns.
  3. 🏷️ BIO Preview — Jumps to the BIO tab and loads the current token-tag breakdown.
  4. 🗑️ Clear — Removes ALL annotations after a confirmation prompt. This cannot be undone!
  5. 💾 Save Draft — Saves with status in_progress. Come back and continue later.
  6. ✅ Mark Complete — Saves with status completed. Only completed resumes are included in training data exports.

🧩 Common Edge Cases & How to Handle Them

⚠️ Date ranges with "Present" or "Current" — e.g. "Jan 2020 – Present". The word "Present" MUST be included inside the WORK_DATE span. Do NOT stop your selection before it.
⚠️ Organisation + Location on the same line — e.g. "DBS Bank, Singapore". Create TWO separate annotations: ORGANIZATION for "DBS Bank" and LOCATION for "Singapore". Do NOT label the full line as one entity.
⚠️ Combined Gender/Age field — e.g. "Female/22" or "Male / 35". Label the entire combined string as GENDER — do NOT split gender and age into separate spans. The age is considered part of that single field value.
💡 Marital Status field — e.g. "Single", "Married", "Divorced". Label only the status VALUE as MARITAL_STATUS, not the field label ("Status:") itself.
💡 Qualifications with honours — e.g. "B.Eng (Hons)". Include the full string including the honours notation inside the DEGREE span.
💡 Multiple phone numbers — label each number as a separate PHONE annotation, not both in one span.
💡 NRIC/Passport numbers — always label the full alphanumeric string including any trailing letter (e.g. "S9243711F").

📤 Exporting Data

Two types of exports are available from the main queue page (← Back):

  1. 📊 Export CSV — Talent database profile in Excel-compatible CSV. One row per candidate. Nested fields (Work Experience, Education, tags/skills) are stored as JSON inside their cells. Open in Excel and use Data → Text to Columns or Power Query to expand them.
  2. 📋 Export JSON — Same talent database profile but as a clean JSON array. One object per candidate with all structured fields. Ready to import into your CRM or ATS system.
  3. 🤖 Export Training Data — NER model training formats: CoNLL-2003, spaCy v3 JSON, HuggingFace JSONL, or full metadata JSON. Only for ML/NLP use — not for the talent database.
💡 Profile exports (CSV/JSON) include all annotated fields: Name, Phone, Email, Current Company, Current Title, Current Location, Expected Location, Gender, Function, Industry, Summary, Language Skills, Work Experience, Education, Project Experience, and skill tags. Only Team, Last Contact, and Created By require manual input in your talent database.
💡 Only resumes with status completed are included by default. You can choose in_progress or all when prompted.
